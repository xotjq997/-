# 로컬 RPA 에이전트

세무사랑 Pro가 **설치되어 있는 Windows PC**에서 실행하는 프로그램입니다.

## 이 프로그램이 하는 일

1. 구글 드라이브의 **"RPA_원천세"** 스프레드시트에서 급여자료를 읽는다.
   (열 구성: 회사명 / 사업자등록번호 / 이름 / 급여구분 / 금액. 급여구분 값은
   `1_정규직근로자`, `2_일용직근로자`, `3_사업소득자`, `4_기타소득자` 중 하나.)
2. 회사(회사명+사업자등록번호)별로 묶어서, 회사 하나씩 순서대로 처리한다.
3. 회사마다: 세무사랑 Pro에서 해당 회사로 변경 -> 그 회사에 있는 급여구분마다
   (근로소득관리/일용직근로소득관리/사업소득관리/기타소득관리 탭에서)
   등록 화면에 사원(소득자) 정보 입력 -> 급여자료입력 화면에 금액 입력 -> 마감.
4. 급여구분 처리가 모두 끝나면 세무신고서류 탭에서 원천징수이행상황신고서 ->
   지방소득세납부서(명세서) 중 현재회사 지방소득세 계산서/납부서를 순서대로
   작성 -> 마감한다.
5. 처리 결과(완료/오류)를 "RPA_원천세" 스프레드시트의 "처리로그" 탭에 기록한다.

## 세무사랑 Pro 자동화에 대한 중요한 한계

세무사랑 Pro는 한국세무사회가 배포하는 상용 프로그램으로, **공개 API나 공개된 UI
자동화 스펙이 없습니다.** 따라서 `setax_automation.py`와 `config.example.yaml`에 있는
메뉴 경로/버튼 컨트롤ID는 전부 **placeholder**이며, 실제 프로그램 화면을 열어서
`inspect_controls.py`로 진짜 값을 확인해야만 동작합니다.

또한 사원등록/사업소득자등록 등 "등록" 화면은 실제로는 이름 외에도 주민등록번호,
입사일, 계좌번호 등 더 많은 항목을 요구할 가능성이 높습니다. "RPA_원천세" 시트에
필요한 컬럼을 자유롭게 추가하고, `config.yaml`의 해당 화면 `field_control_ids`에
`컬럼명: 컨트롤ID`를 추가하면 코드 수정 없이 그대로 반영됩니다.

이 부분은 실제 프로그램에 접근한 사람이 한 번 채워야 하는 설정값이지, 코드만으로
미리 알 수 있는 정보가 아닙니다.

## 설정 순서

1. `pip install -r requirements.txt`
2. `config.example.yaml`을 `config.yaml`로 복사하고 값을 채운다.
3. Google Cloud 콘솔에서 서비스 계정을 만들고 키(json)를 발급받아, "RPA_원천세"
   스프레드시트에 해당 서비스 계정 이메일을 "편집자"로 공유한다.
4. 세무사랑 Pro를 실행한 상태에서:
   ```
   python inspect_controls.py
   ```
   출력된 컨트롤 트리에서 회사변경/사원등록/급여자료입력/마감/세무신고서류 등
   각 화면의 메뉴·버튼·입력창 automation_id를 찾아 `config.yaml`의 값들을 채운다.
5. `config.yaml`의 `setax_pro.dry_run: true` 상태로 먼저 실행해서 로그만 확인한다:
   ```
   python run_pipeline.py config.yaml
   ```
6. 로그에 찍히는 순서(회사 변경 -> 등록 -> 자료입력 -> 마감 -> 세무신고서류 -> 마감)가
   기대한 대로인지 확인한 뒤에만 `dry_run: false`로 바꾼다.

`run_pipeline.py`는 상시 실행되는 프로세스가 아니라, 실행할 때마다 그 시점의
"RPA_원천세" 시트 내용을 한 번 읽어 전체 회사를 처리하고 종료하는 **1회성 배치**다.
매월 처리 시점에 수동으로(또는 Windows 작업 스케줄러로) 실행하면 된다.

## 안전 수칙 (반드시 읽을 것)

- **처음에는 반드시 세무사랑 Pro의 테스트/연습 회사 코드로 검증하세요.** 실제 신고
  데이터가 걸린 회사에 바로 자동입력을 시도하지 마세요.
- RPA가 입력을 마친 뒤에도 **신고 접수 전에 화면에서 값을 사람이 육안으로 재확인**하세요.
  원천세 신고 오류는 가산세 등 실제 금전적/법적 불이익으로 이어질 수 있습니다.
- 세무사랑 Pro가 업데이트되면 화면 구성이 바뀌어 automation_id가 달라질 수 있습니다.
  업데이트 후에는 `inspect_controls.py`로 다시 확인하세요.
- 한 회사 처리 중 오류가 나면 그 회사는 "처리로그"에 오류로 기록하고 다음 회사로
  넘어가도록 되어 있다. 오류가 기록된 회사는 원인을 확인하고 수동으로 마무리하세요.
