# 설치/설정 가이드

## 전체 흐름

```
[담당자] 구글드라이브 "RPA_원천세" 스프레드시트에 이번 달 급여자료 입력
        │  (회사명 / 사업자등록번호 / 이름 / 급여구분 / 금액)
        ▼
[로컬 RPA 에이전트 (Python, 세무사랑 Pro가 설치된 PC에서 실행)]
        → "RPA_원천세" 시트를 읽어 회사별로 그룹핑
        → 회사마다 세무사랑 Pro에서 회사 변경
        → 급여구분별(정규직/일용직/사업소득자/기타소득자) 화면에
          등록 → 자료입력 → 마감
        → 세무신고서류 탭에서 원천징수이행상황신고서, 지방소득세납부서 작성 → 마감
        → 처리 결과를 "RPA_원천세" 시트의 "처리로그" 탭에 기록
        ▼
[세무사랑 Pro] 원천세 신고서 작성 화면에 데이터 반영 (사람이 최종 확인 후 신고 접수)
```

핵심 이유: 세무사랑 Pro는 데스크톱 프로그램이라 클라우드에서 화면을 조작할 수
없습니다. 그래서 화면 자동입력(RPA)은 세무사랑 Pro가 설치된 PC에서 도는
`local-agent`가 구글시트를 직접 읽어 전 과정을 수행합니다. 세액 계산 자체는
세무사랑 Pro가 사원등록/급여자료입력 시점에 자체적으로 수행하므로, 이 저장소는
별도의 세액 계산 로직을 두지 않습니다.

## 1단계: "RPA_원천세" 스프레드시트 준비

1. 구글 드라이브에 "RPA_원천세"라는 이름의 스프레드시트를 만든다 (또는 기존 것 사용).
2. 첫 번째 워크시트에 다음 헤더로 컬럼을 만든다: `회사명`, `사업자등록번호`, `이름`,
   `급여구분`, `금액`.
   - `급여구분`에는 반드시 다음 네 값 중 하나를 그대로 입력한다:
     `1_정규직근로자`, `2_일용직근로자`, `3_사업소득자`, `4_기타소득자`
3. 세무사랑 Pro의 등록 화면(사원등록 등)에 이름/금액 외 추가 정보(주민등록번호,
   입사일 등)가 필요하면 컬럼을 자유롭게 추가한다. 코드 수정 없이 `config.yaml`에서
   컬럼명으로 참조할 수 있다.
4. 급여자료는 회사별로 여러 행을 넣어두면 되고, 같은 스프레드시트 안에 여러
   회사 자료를 함께 넣어도 된다 (에이전트가 회사명+사업자등록번호로 자동 분리).

## 2단계: 로컬 RPA 에이전트 설정 (세무사랑 Pro가 설치된 PC)

`local-agent/README.md`를 따라 설치한다. 요약:

1. Python 패키지 설치, `config.yaml` 작성 (스프레드시트 ID, 서비스 계정 키 경로 포함).
2. Google Cloud 서비스 계정을 만들고, 그 이메일을 "RPA_원천세" 시트에 편집자로 공유.
3. `inspect_controls.py`로 세무사랑 Pro의 실제 화면 컨트롤 ID를 확인해 `config.yaml`에 반영.
   (이 저장소는 세무사랑 Pro 내부 구조를 모르므로 이 단계는 실제 프로그램을 열어본
   사람이 직접 해야 한다.)
4. `dry_run: true`로 먼저 검증 후, 이상 없으면 `false`로 바꿔 실제 실행.

## 3단계: 매월 급여 처리

1. "RPA_원천세" 시트에 이번 달 급여자료를 입력한다 (회사별로, 급여구분별로).
2. 세무사랑 Pro를 실행해 둔 상태에서 로컬 에이전트를 돌린다:
   ```
   python run_pipeline.py config.yaml
   ```
3. 콘솔 로그와 "처리로그" 탭에서 회사별 처리 결과(완료/오류)를 확인한다.
4. 세무사랑 Pro 화면에서 각 회사의 급여자료·원천징수이행상황신고서·지방소득세납부서
   내용을 사람이 육안으로 재확인한 뒤 최종 신고를 진행한다.

## 컴플라이언스 주의사항

- 원천세 신고는 법적 책임이 따르는 업무입니다. 이 자동화는 **입력 보조 도구**이며,
  최종 신고 전 반드시 담당 세무사/직원이 세무사랑 Pro 화면에서 값을 검토해야 합니다.
- 처음에는 반드시 세무사랑 Pro의 테스트/연습 회사로 검증한 뒤, 실제 회사 자료에
  적용하세요.
